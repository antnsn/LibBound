# Service (portals, lockboxes) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A shared LibBound module that announces a class service in Trade on a key press and alerts on requests in chat, used by Chronobound (portals) and Shadowbound (lockboxes).

**Architecture:** `LibBound/Service.lua` holds pure functions (word split, match, template fill; unit-tested with plain `lua5.1`) and `lib.InstallService(ns, service)`, which adds settings, a chat listener, the alert line with `addon:` links, the announce button/key/slash command and an options page. Each addon adds one `Service.lua` that only declares its service.

**Tech Stack:** Lua 5.1, WoW Forever client (Interface 16001), LibStub, wowbench scenarios, luacheck.

**Spec:** `LibBound/docs/superpowers/specs/2026-11-25-service-design.md`

## Global Constraints

- Only API listed in `~/code/wowbench/api/client.txt`; resolve chat/party functions at call time (`C_ChatInfo.SendChatMessage or SendChatMessage`), never cache them at load.
- Secret chat payloads: skip a message when `lib.IsSecret(text)` or `lib.IsSecret(sender)`; never compare a secret.
- LibBound `MINOR` 32 → 33; `Service.lua` goes in `LibBound.xml` before `BuffTimer.lua`; first line after the header: `if not lib or not lib.installing then return end`.
- Per-addon state only through `ns`; the one shared thing is the `SetItemRef` hook, installed once per LibBound copy, dispatching by addon name.
- Settings keys (per addon db): `serviceOn`, `serviceMessage`, `serviceTriggers`, `serviceChannel`, `serviceInterval`, `serviceSound`, `serviceAutoWhisper`, `serviceReply`, `serviceKey`, `serviceSkill` (Shadowbound fallback). Defaults: on=true, channel="Trade", interval=60, sound=true, autoWhisper=false, message/reply = the service's examples.
- Dedupe 60 s per sender for alerts; auto-whisper once per sender per 600 s, never in combat, never when `available()` is false.
- Intent words: `wtb lf lfm need needs any anyone port plz pls please can someone` or a `?` in the text.
- Competing offer markers: `wts selling offering tips` and the phrases `/w`, `whisper me`, `w me`, `lf customers`.
- Chat line: `[<Title>] <sender>: <text>  [Invite] [Whisper]`; link format `addon:bound:<addonName>:invite:<sender>` / `...:whisper:<sender>`.
- Each repo: `main` protected, branch `service`, `/codex:review` before each commit, signed commits with the Co-Authored-By line, PR + squash merge; LibBound merges first.

## Review Focus

1. Sender names with realm (`Thrall-Ashborne`) and names with non-ASCII letters: links and invites must carry the full name unchanged → test in Task 2 (link round-trip with `Ståle-Ashborne`).
2. The message box left empty or only spaces: announce must refuse with a note, not post an empty line → Task 2 test.
3. Template with `%` characters (`50% off`) or unknown `{x}`: fill must not error and keeps the text → Task 1 test.
4. The player's own messages in Trade (his announce echoes back) must not alert → Task 2 test.
5. Upper case and punctuation ("WTB PORT ORG!!", "port->uc?") must match → Task 1 test.
